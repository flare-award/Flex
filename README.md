# Flex

Бесплатный аналог Discord для двоих (и небольших компаний): серверы, текстовые и голосовые каналы через сервер-релей, личные сообщения, реакции, файлы, экранная демонстрация.

## Hugging Face Spaces (Docker)

Репозиторий готов к запуску как Docker Space: Dockerfile собирает клиент и запускает Express/Socket.IO на `0.0.0.0:7860`. Создайте Space с SDK **Docker**, подключите этот GitHub-репозиторий и включите **Persistent Storage**. HF монтирует его в `/data`; там хранятся `db.json`, загрузки и резервные копии.

В настройках Space добавьте secrets/variables:

- `JWT_SECRET` — случайное секретное значение длиной не менее 32 байт;
- `FLEX_DATA_DIR=/data`;
- `PORT=7860` (Dockerfile уже задаёт это значение).

Клиент и API обслуживаются с одного origin, поэтому production CORS намеренно отключён, а Socket.IO поддерживает WebSocket и polling. Голос передаётся бинарными Opus/WebM-фрагментами через серверный Socket.IO relay, а не через P2P.

## Возможности

- **Профиль:** имя (любые символы, 32), никнейм (строчная латиница + `-` `_` `~`, смена раз в 15 мин), аватар круглый (до 10 МБ, png/jpg/gif/webp), баннер (558×197 автоподгон или просто цвет), градиент профиля (два цвета, HEX + пикер), статусы онлайн/отошёл/не беспокоить/невидимка, «О себе», кастомный статус, кол-во друзей и т.п.
- **Серверы:** создание, иконка/баннер, инвайт-коды и ссылки вида `/invite/КОД`, вертикальная панель слева со значками и бейджами непрочитанных/упоминаний.
- **Каналы и категории:** текстовые и голосовые, категории, переименование/удаление, приватный флаг.
- **Чат:** реалтайм, редактирование/удаление своих сообщений, вложения (drag&drop/вставка/кнопка), реакции, ответы на сообщения, закрепы, упоминания `@ник`, форматирование `**bold** *italic* __underline__ ~~strike~~` \`код\` и ```код-блоки```, ссылки, индикатор «печатает».
- **Голос:** серверный релей (не P2P!) — работает ВСЕГДА между любыми странами/NAT; определение говорящего (кольцо + уровень звука), мут/деф, серверный мут для модераторов (красные иконки).
- **ЛС и друзья:** DM 1-на-1, заявки в друзья, подтверждение, быстрые переходы в ЛС.
- **Роли и права:** цветные никнеймы по роли, владелец/админ/модер/участник, битовая маска разрешений.
- **Уведомления:** бейджи на серверах/каналах, браузерные нотификации, тосты.
- **Темы:** тёмная по умолчанию, светлая и кастомная (в разработке переключение в настройках).

## Локальный запуск (для разработки)

```bash
cd Flex
npm install
npm run install:all
npm run dev             # сервер :4000, клиент :5173
```

Открой http://localhost:5173. При первом запуске создаются демо-аккаунты `demo@flex.app / demo1234` и `friend@flex.app / friend1234`, чтобы можно было проверить звук вдвоём в двух вкладках.

## Бесплатный деплой на GitHub Pages + Glitch

Вам понадобятся:
- Аккаунт на **GitHub** (бесплатно).
- Аккаунт на **Glitch.com** (бесплатно, без карты — логинимся через GitHub).
- (Опционально) Аккаунт на **UptimeRobot** (бесплатно), чтобы Glitch не засыпал.

### 1. Залейте код на GitHub

1. Создайте на GitHub новый **публичный** репозиторий, например `flex`.
2. Пушами из локальной папки:
   ```bash
   cd Flex
   git init
   git add .
   git commit -m "initial"
   git branch -M main
   git remote add origin https://github.com/ВАШ_НИК/flex.git
   git push -u origin main
   ```

### 2. Поднимите бэкенд на Glitch

1. Откройте https://glitch.com/ и нажмите **New Project → Import from GitHub**, вставьте `https://github.com/ВАШ_НИК/flex.git`.
2. Glitch сам установит зависимости, соберёт клиент и запустит сервер — подождите минуту.
3. Нажмите **Share → Live App** и скопируйте URL вашего бэкенда, например: `https://my-cool-flex.glitch.me`.
4. (Рекомендуется) В левой панели Glitch откройте `.env` и добавьте:
   ```
   JWT_SECRET=любая-длинная-случайная-строка
   CORS_ORIGIN=https://ВАШ_НИК.github.io
   ```
   Если у вас кастомный домен на Pages, укажите его через запятую.
5. Нажмите **Tools → Terminal** и выполните: `refresh` — проект перезапустится.

⚠️ Важно: Glitch хранит файлы проекта в папке `.data` (она сохраняется при перезапусках). Бэкенд сам сохраняет БД и загрузки туда, ничего дополнительного настраивать не нужно.

### 3. Включите GitHub Pages с указанием бэкенда

Файл готового GitHub Actions workflow лежит в `docs/github-actions-deploy.yml`. Включить автодеплой:

1. Создайте в репозитории папку `.github/workflows/` и положите туда файл `docs/github-actions-deploy.yml` (переименуйте как `deploy.yml`).
2. В **Settings → Secrets and variables → Actions → New repository secret** добавьте секрет:
   - Имя: `FLEX_API_URL`
   - Значение: URL вашего Glitch-бэкенда, например `https://my-cool-flex.glitch.me`
3. В **Settings → Pages** в разделе **Source** выберите **GitHub Actions**.
4. Зайдите на вкладку **Actions**, выберите workflow `Deploy to GitHub Pages` и нажмите **Run workflow**.
5. Через минуту у вас появится сайт на `https://ВАШ_НИК.github.io/имя-репо/`. Откройте его — вы должны увидеть страницу входа.

Если не хочется настраивать Actions — можно вручную собрать клиент и закинуть содержимое `client/dist` в любую статику (Netlify, Vercel, Cloudflare Pages, даже просто `python -m http.server`). При сборке укажите бэкенд:
```bash
cd client
VITE_API_URL=https://my-cool-flex.glitch.me npx vite build
```

После этого делитесь ссылкой с другом — он сможет зарегистрироваться сам, и вы будете общаться. Приглашение на сервер можно дать ссылкой вида `https://ВАШ_НИК.github.io/flex/invite/КОД` (код выдаётся через меню сервера «Пригласить»).

### 4. UptimeRobot (чтобы Glitch не засыпал)

На бесплатном тарифе Glitch «засыпает» после 5 минут без запросов и при старте думает 2–3 секунды. Чтобы он работал 24/7:

1. Зарегистрируйтесь на https://uptimerobot.com/ (бесплатный план).
2. Добавьте **HTTP(s) monitor**: URL = `https://ваш-проект.glitch.me/healthz`, интервал 5 минут.
3. UptimeRobot будет пинговать бэкенд каждые 5 минут — проект не уснёт.

Этого хватает для двоих (фактически и для 5–10 человек, если голос одновременно не все включают).

### Обновление

Каждый пуш в `main` автоматически пересоберёт и выложит фронтенд на Pages. Обновить бэкенд на Glitch можно кнопкой **Tools → Import and Export → Import from GitHub** (либо включите автоматический импорт в настройках Glitch).

```

│   └── src/

│       ├── auth.js        # JWT + валидация никнеймов
│       └── voice-relay.js # Серверная ретрансляция аудио
├── client/                # React + Vite + Tailwind
│   └── src/
│       ├── state/         # Auth, AppState (сокет, голос, сообщения)
│       ├── components/    # UI
│       ├── voice/         # VoiceEngine (запись/воспроизведение)
│       └── utils/
├── .github/workflows/     # Автодеплой на Pages
├── glitch.json            # Команды запуска на Glitch
├── Dockerfile             # Для VPS-деплоя (альтернатива Glitch)
├── docker-compose.yml
└── deploy.md              # Инструкция для VPS + Caddy + HTTPS
```

## Резервные копии и данные

- **На Glitch:** БД и файлы лежат в `.data/` внутри проекта, не удаляются при рестарте. Чтобы сделать бэкап: в Glitch → Tools → Terminal → `cp .data/db.json .data/db-$(date +%F).json` и скачайте файл.
- **На сервере/VPS:** хранятся в `data/`, делаются почасовые бэкапы на 48 часов.
- **Важно:** на бесплатном тарифе Glitch проект приватным быть не может (код виден в редакторе). JWT_SECRET в `.env` защищает аккаунты, но если хотите приватность — используйте VPS-вариант (`Dockerfile` + `deploy.md`).

## Устранение проблем

- **Ошибка сети при входе:** откройте консоль браузера (F12) и посмотрите, на какой URL уходит запрос. Он должен быть тот же, что вы указали в `FLEX_API_URL`. Если забыли указать секрет — пересоберите workflow.
- **Звук не работает:** для микрофона на GitHub Pages и Glitch по умолчанию уже есть HTTPS, так что браузер разрешит доступ. Если на локалке без HTTPS — используйте http://localhost:5173 (в Chrome для localhost микрофоны разрешены).
- **Голос с задержкой:** если сервер Glitch в США, пинг из РФ/МД может быть 150–200 мс. В таком случае лучше поднять бэкенд на VPS в Москве/Франкфурте (см. `deploy.md`).
